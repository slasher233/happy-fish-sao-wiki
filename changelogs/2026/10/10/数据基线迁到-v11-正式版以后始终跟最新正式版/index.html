    数据基线迁到 v1.1 正式版（以后始终跟最新正式版）

    v1.1 正式版发布后，本站与需求单仓库（happy-fish-patch-plan）的数据​基线​从​v1.0​母图​迁到​v1.1​正式版：Wiki 里所有「现值」（cur_ 列）、对象数、页脚指纹现在都取自 v1.1；同时把「换基线」做成一条可重复的命令，以后 v1.2、v1.3 发布都照同一套流程走。母图（v1.0）依然一字未改，只作只读锚点。

    一​、​为什么​要​迁¶

    基线决定了三件事：Wiki 页面上的「现值」、需求单里 cur_ 列（现值列，只读）的来源、以及校验器判断「对象是否存在 / 字段是否存在」的依据。v1.1 已经进 Custom Maps 并成为玩家实际下载的版本，基线继续挂在 v1.0 会让所有页面与 2.61 之后的实际数值脱节。

    二​、​迁移​做​了​什么¶

    1. 快照​归档：迁移前的 v1.0 产物（对象 dump、索引、wiki 数据）整份归档到 note_log\index\archive\v1.0\ 与 note_log\wiki_data\archive\v1.0\，可随时比对。
    2. 重抓​对象​层：从 v1.1 的 war3map.w3t/w3u/w3a 重新导出对象 dump（校验 byte_roundtrip=true），重建索引与 wiki 数据。w3u 部分与 v1.0 逐字​节​相同，​说明​链路​没有​引入​额外​改写​。
    3. 换​身份：patch_plan\maps_sha256.json 与 note_log\index\baseline_identity.json 改为 v1.1。Wiki 侧身份不再写死，改为读​这份​JSON，​所以​以后​换​基线​时​Wiki​会​自己​跟着​走​。
    4. cur_ 列重取：需求单里 12 张表的现值列按 v1.1 实测值重写，并重算 index\baseline_cur.json（校验器用它检测「现值列被手改」，换基线后必须同步重生成）。
    5. 意图​去​重​（​消费​）：​换​基线​后​，​过去​几个​月​提​的​改动​意图​里​有140​条​已经​在​v1.1​里​生效（​例如​issue​#​2​新建​的​10​件​装备​与​45​个​技能​、​issue​#​3​的​一批​属性​数值​、​issue​#​6​七皇​の​统治者​）​。​这些​行​按​「​意图​=​现值​」​自动识别​、​清空​意图​列​并归档​留痕；​剩下58​条仍​待办​，​原样​保留​。
    6. 链路​加固：build_patch_plan.py 不再写死母图路径与 v1.0 身份，改为从已有 maps_sha256.json 继承身份；issue #2 的追加逻辑会跳过「基线里已存在」的对象。

    三​、​留下​的​58​条​待办¶

    类型 条数 例子

    介绍​栏​文案​重写​（​issue​#​3​/​#​4​/​#​6​） 18 彩色​数值​排版​与​说明​文字
    新增​BOSS​掉落​（​issue​#​2​） 10 第​51​–​60​组​：​新​装备​掉落​地图​里​的​BOSS

    全部逐行清单留档在 patch_plan\data\archive\v1.1\pending_rows.csv（已生效的 140 条在 applied_changes.csv），并随仓库推送。

    四​、​以后​怎么​再换​一次¶

    python note_log\tools\rebase_baseline.py --map latest --steps snapshot,dump,index,wiki_data,identity   # 抓新基线
python note_log\tools\build_patch_plan.py                                                              # 重建数据表（保留意图）
python patch_plan\tools\validate.py                                                                    # 校验
python note_log\tools\rebase_baseline.py --map latest --steps consume                                  # 消费已生效意图

    --steps consume 只清空「意图与基线现值相同」的格子，并在 data\archive\<版本>\ 留下三项证据：applied_changes.csv（生效了什么）、pending_rows.csv（还欠什么）、spec\（换基线那一刻的需求单快照）。rebase_baseline.py 的路径全部由脚本位置推导，换机器可用环境变量 HFX_WORK_ROOT / HF_OBJECT_TOOL 覆盖。

    五​、​影响​与​边界¶

    • Wiki​页面：​物品​/​技能​/​英雄​页​的​现值​、​数量​、​页脚​指纹​已切​到​v1.1​（​物品​551​→​561​、​技能​2​,​199​→​2​,​266​）​。历史​更新​日志​保持​原样—​—​生成器​原先​会​顺手​把​v1.0​基线​帖​改写​成​当前​身份​，​本次​已​改成​「​只​在​缺​文件​时​生成​」​，​v1.0​帖​恢复​为​原文​。
    • 母图​不动：v1.0 母图仍是只读锚点，SHA256 未变；仓库里的 maps_sha256.json 记的是「当前基线 = v1.1」，同时保留 v1.0 身份为 previous_baseline。
    • 仍​未​实机​验证：​技能​解锁​等级​、​专属​装备​绑定​等​取证​项​，​页面​里​仍​标注​「​待​考证​」​；​数值​与​手感​仍​需​人工​确认​。
