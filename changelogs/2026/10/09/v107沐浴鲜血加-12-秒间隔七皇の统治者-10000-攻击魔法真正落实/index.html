    v1.07：沐浴鲜血加 1.2 秒间隔、七皇の统治者 +10000 攻击/魔法真正落实

    作者​实测​v1.06​后​又​发现​两处​需要​收尾​的​地方​：王女​之冠的​「​沐浴​鲜血​」​吸血​已经​生效​，​但​没有​间隔​—​—​攻速​快​或​一次​打多​目标​时会​连续​回血​，​因此​加1.2​秒​间隔；七皇​の​统治者的 +​10000​攻击与 +​10000​魔法在​游戏​里​没有​效果​，​本版​查出​原因​是​「​物品​技能​栏​上限​」​，​改走​母图​自带​的EXEQ​装备​系统授予​，​并​同步​补​上​介绍​栏里​的​这​两行​数值​。

    一​、​沐浴​鲜血​：​为什么​要加​1.2​秒​间隔¶

    v1.06​的​吸血​实现​是​「每次​造成​伤害都​回​30%​」​，​没有​节流​：

    // v1.06：note_log/work/hfx6_module.j —— HFX5_DmgAct 攻击方 I0Q9 分支
call HF22LS_Heal(src,dmg*0.30)   // dmg = GetEventDamage()

    结果是普攻命中回一次、技能伤害也回一次、一次打多目标则每个目标各回一次，攻速越快回得越频繁。母图里同类吸血装备（真红白之圣灵剑 I06O）的做法是带​间隔的：它的动作里 DisableTrigger → 结算 → nY(1.) → EnableTrigger，即 1 秒内不再重复结算。

    v1.07​给​沐浴​鲜血​加1.2​秒​间隔，​语义​与​真​红白​一致​—​—节流​，​不​累积：​间隔​内​造成​的​伤害​不​回血​，​1.2​秒​后​下​一次​造成​伤害​才​再​回​一次​。

    实现​沿用母图​自己​的​间隔​写法（母图把「一段时间内只做一次」统一交给 PH_Bzv）：

    // note_log/work/hfx7_module.j（v1.07 版）
function HFX5_BloodReady takes unit u returns boolean
    if LoadInteger(PH_Xs,StringHash(I2S(GetHandleId(u))+"HFX5blood"),0)!=0 then
        return false                                    // 还在 1.2 秒间隔里 → 本次不回血
    endif
    call PH_Bzv(u,1.2,"HFX5blood")                       // 置位：1.2 秒后由母图定时器自动清位
    return true
endfunction

    回血​那​一行​随之​包进​判断​：

    if HFX5_BloodReady(src) then
    call HF22LS_Heal(src,dmg*0.30)
endif

    PH_Bzv（war3map.j:59037）做的事就是「立刻把标记置 1 + 起一个一次性定时器，N 秒后把标记清 0」，母图自己的道具时限技能也用它，因此不需要额外的计时器或全局变量。

    二​、​七皇​の​统治者​：​+​10000​攻击​/​魔法​为什么​没​落实¶

    v1.05 给七皇の统治者（I0H6）新建了两个被动技能并把它们追加到物品技能栏：

    技能 模板 效果
    Y03F A00P（AItn 系） Iatt = 10000（+10000 攻击）
    Y040 X018（AI2m 系） Iman = 10000（+10000 魔法值）

    排查（note_log/work/230–235_probe_qihuang*.txt）发现两件事：

    1. 对象​层​没有​问题。Y03F/Y040 都在 war3map.w3a 的自定义表里，字段与模板逐字段一致，I0H6.iabi 里也确实写着它们；但母图 551 件物品的技能栏（iabi）上限就是 6 条（官方 2.43 ItemData.slk 的上限是 5 条；全图 6 条的只有 I0H6 与 J0H6）。追加后 I0H6 变成 8​条，​第​7​/​8​条​被​引擎​忽略​—​—​与​实测​「​没有​效果​」​吻合​。
    2. 介绍​栏​从来​没写​过​这两项。母图的 I0H6 介绍栏（ides/utub）里只有筋力/敏捷/体力/生命值/魔法防御/防御和两个技能名，即便加成生效，玩家在物品说明里也看不到。

    而​母图​自己​对​「​大额​攻击​/​全部​魔法值​」​加成​的​做法​是走​脚本​的​EXEQ​装备​系统：EXEQ_Reconcile（war3map.j:88137，拾取/丢弃事件 + 每秒 EXEQ_PeriodicReconcile 都会跑）里有一串 call EXEQ_Ability(EXEQL_u,'XXX',条件)，其中 X00R/X009 就是 AIat 系攻击被动、X018 就是 AI2m 系魔法被动。

    三​、​v1.07​的​做法¶

    • 物品​技能​栏回到​母图​原有​6​条（不再追加 Y03F/Y040；两个技能对象仍保留在 war3map.w3a 里，只是改由脚本授予）。
    • 在 EXEQ_Reconcile 里插两行，按背包里是否持有 I0H6 授予/移除：
    call EXEQ_Ability(EXEQL_u,'Y03F',EXEQ_Has(EXEQL_u,'I0H6'))
call EXEQ_Ability(EXEQL_u,'Y040',EXEQ_Has(EXEQL_u,'I0H6'))

    EXEQ_Ability 自己用 EXEQ_State 记住状态（UnitAddAbility + UnitMakeAbilityPermanent，卸下时移除），而且 EXEQ_Reconcile 前后本来就保存/还原 maxHP/maxMP，属性变化不会引起掉血或蓝量异常。

    • 介绍栏（ides/utub）补上两行：
    项 v1.06 v1.07
    I0H6.iabi A0SA,A0PH,A0TE,Q15A,Q23R,Q23D,Y03F,Y040（8 条，被忽略） A0SA,A0PH,A0TE,Q15A,Q23R,Q23D（​6​条​）​+​EXEQ​授予
    介绍​栏 …​生命​值​:​10000​/​魔法​防御​:​50​… …​生命​值​:​10000​/攻击力​:​10000 / 魔法值​:​10000/​魔法​防御​:​50​…

    五​、​验证​与​已知​边界¶

    • 数据​层：validate.py → 改动行 216｜​错误0｜​警告0；​计划​新增​对象​物品10｜​技能67。
    • 五层​静态​验证（note_log/work/verify_v107.py）：110​项​通过​/​0​项​失败 —— 逐字段回读 I0H6.iabi 回到 6 条且 ides/utub 含两行新数值、Y03F/Y040 对象仍在、脚本层 call PH_Bzv(u,1.2,"HFX5blood") 与 if HFX5_BloodReady(src) then 各 1 处、两条 EXEQ_Ability 授予各 1 处、pjass 零错误、标题三处为 刀剑物语 happy丶FISH v1.07、成员层差异（C→最终 3 个变更 + 9 个图标）、母图指纹未变。仍未进​游戏​实测​。
    • 已知​边界​：
    • 1.2​秒​间隔​是节流（​间隔​内​的​伤害​不​回血​、​不​累积​）​，​与​真​红白​之​圣灵​剑​的​间隔​同​语义​；​如果​希望​「​攒​到​下​一次​一起​回​」​需要​另改​实现​。
    • 「​物品​技能​栏​上限​」​没有​找到​官方​文档​：​Hive​的​讨论​只​说明​编辑器​的​4​个​槽​位​是编辑器限制​（​Shift​+​Enter​可填​更​多​）​，​运行​时​上限​是​以​「​官方​最​多​5​条​、​母图​最多​6​条​、​且​第​7​/​8​条​实测​无效​」​推断​的​—​—​因此​本版​不去​赌​这个​上限​，​直接​改走​EXEQ​。
    • 第​24​条​「​抵抗​」​仍​按​v1.05​拍板暂​不​实现。
