    数值​缺失​：​从​「​空着​」​变成​「​说​清​为什么​空​」¶

    以前物品页/英雄页遇到缺失值是什么都不写或只写一个 —，现在统一成三态表达：

    写法 含义
    —（对象数据中此字段为空） 字​段​存在​，​值​是​空​字符串
    未设置（对象数据里没有这一项） 对象​数据​里​根本​没有​这个​字​段​（​物品​等级​、​价格​）
    未设置（对象数据 icla 字段为空） 具体​字段名​+​空值​原因​（​类型​）
    无数据（说明里没写品质） 只能​从​说明​文本​推断​、​而​文本​里​没​写
    本节无内容：…（说清查了哪些数据） 整个​小节​确实​没有​证据​，​附​检索​依据
    • 技能总览的 NUL 对象 ID 回退到原型名（A000 一类），确实无 ID 才写「（对象无 ID）」（对应清单 W018）。
    • 技能​名​/​原型​名​空值​分​「​（​未​设置​名称​）​」​「​该​技能​对象​未​设置​名称​与​原型​名​，​请​用​ID​检索​」​（​W019​）​。
    • 物品图标/物品类型等 WC3 英文枚举（Miscellaneous、Permanent…）已映射为中文，并保留原始枚举名（W002）。
    • 「触发时赠予」表的触发器内部枚举 unclassified_give 已中文化（W012，剩 1 页 2 处待清）。

    顺带​修掉​一个​线上​404¶

    页脚​的​站点​级​免责​句​原本​写站点​绝对​链接 [地图身份](/info/地图身份/)。本站是 GitHub Pages 项目​站（site_url: https://slasher233.github.io/happy-fish-wiki/，仓库里没有 CNAME），根相对链接会被解析成 https://slasher233.github.io/info/地图身份/ → 404，​而​这条​页脚​在​582​个​页面​上​都​有​。

    现在 write_page() 会按页面深度把绝对链接改写成相对链接：docs/index.md → info/地图身份.md，docs/heroes/X.md、docs/skills/index.md、docs/info/X.md → ../info/…，docs/items/装甲/X.md、docs/changelogs/posts/X.md → ../../info/…。构建后全站绝对链接残留 0​页​/​0​处，抽查产物 HTML 的页脚 href 均为相对路径。
