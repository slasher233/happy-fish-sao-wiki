v1.1 正式版发布后，本站与需求单仓库（`happy-fish-patch-plan`）的**数据基线从 v1.0 母图迁到 v1.1 正式版**：Wiki 里所有「现值」（`cur_` 列）、对象数、页脚指纹现在都取自 v1.1；同时把「换基线」做成一条可重复的命令，以后 v1.2、v1.3 发布都照同一套流程走。母图（v1.0）依然一字未改，只作只读锚点。

<!-- more -->

## 一、为什么要迁

基线决定了三件事：Wiki 页面上的「现值」、需求单里 `cur_` 列（现值列，只读）的来源、以及校验器判断「对象是否存在 / 字段是否存在」的依据。v1.1 已经进 `Custom Maps` 并成为玩家实际下载的版本，基线继续挂在 v1.0 会让所有页面与 2.61 之后的实际数值脱节。

## 二、迁移做了什么

1. **快照归档**：迁移前的 v1.0 产物（对象 dump、索引、wiki 数据）整份归档到 `note_log\index\archive\v1.0\` 与 `note_log\wiki_data\archive\v1.0\`，可随时比对。
2. **重抓对象层**：从 v1.1 的 `war3map.w3t/w3u/w3a` 重新导出对象 dump（校验 `byte_roundtrip=true`），重建索引与 wiki 数据。`w3u` 部分与 v1.0 **逐字节相同**，说明链路没有引入额外改写。
3. **换身份**：`patch_plan\maps_sha256.json` 与 `note_log\index\baseline_identity.json` 改为 v1.1。Wiki 侧身份不再写死，改为**读这份 JSON**，所以以后换基线时 Wiki 会自己跟着走。
4. **`cur_` 列重取**：需求单里 12 张表的现值列按 v1.1 实测值重写，并重算 `index\baseline_cur.json`（校验器用它检测「现值列被手改」，换基线后必须同步重生成）。
5. **意图去重（消费）**：换基线后，过去几个月提的改动意图里有 **140 条已经在 v1.1 里生效**（例如 issue #2 新建的 10 件装备与 45 个技能、issue #3 的一批属性数值、issue #6 七皇の统治者）。这些行按「意图=现值」自动识别、清空意图列并**归档留痕**；剩下 **58 条**仍待办，原样保留。
6. **链路加固**：`build_patch_plan.py` 不再写死母图路径与 v1.0 身份，改为从已有 `maps_sha256.json` 继承身份；issue #2 的追加逻辑会跳过「基线里已存在」的对象。

## 四、以后怎么再换一次

```bash
python note_log\tools\rebase_baseline.py --map latest --steps snapshot,dump,index,wiki_data,identity   # 抓新基线
python note_log\tools\build_patch_plan.py                                                              # 重建数据表（保留意图）
python patch_plan\tools\validate.py                                                                    # 校验
python note_log\tools\rebase_baseline.py --map latest --steps consume                                  # 消费已生效意图
```

`--steps consume` 只清空「意图与基线现值相同」的格子，并在 `data\archive\<版本>\` 留下三项证据：`applied_changes.csv`（生效了什么）、`pending_rows.csv`（还欠什么）、`spec\`（换基线那一刻的需求单快照）。`rebase_baseline.py` 的路径全部由脚本位置推导，换机器可用环境变量 `HFX_WORK_ROOT` / `HF_OBJECT_TOOL` 覆盖。

## 五、影响与边界

- **Wiki 页面**：物品/技能/英雄页的现值、数量、页脚指纹已切到 v1.1（物品 551 → 561、技能 2,199 → 2,266）。**历史更新日志保持原样**——生成器原先会顺手把 v1.0 基线帖改写成当前身份，本次已改成「只在缺文件时生成」，v1.0 帖恢复为原文。
- **母图不动**：v1.0 母图仍是只读锚点，SHA256 未变；仓库里的 `maps_sha256.json` 记的是「当前基线 = v1.1」，同时保留 v1.0 身份为 `previous_baseline`。
- **仍未实机验证**：技能解锁等级、专属装备绑定等取证项，页面里仍标注「待考证」；数值与手感仍需人工确认。
