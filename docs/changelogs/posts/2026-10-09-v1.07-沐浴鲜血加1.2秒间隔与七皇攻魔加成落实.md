作者实测 v1.06 后又发现两处需要收尾的地方：**王女之冠**的「沐浴鲜血」吸血已经生效，但没有间隔 —— 攻速快或一次打多目标时会连续回血，因此加 **1.2 秒间隔**；**七皇の统治者**的 **+10000 攻击**与 **+10000 魔法**在游戏里没有效果，本版查出原因是「物品技能栏上限」，改走母图自带的 **EXEQ 装备系统**授予，并同步补上介绍栏里的这两行数值。

<!-- more -->

## 一、沐浴鲜血：为什么要加 1.2 秒间隔

v1.06 的吸血实现是「**每次造成伤害**都回 30%」，没有节流：

```jass
// v1.06：note_log/work/hfx6_module.j —— HFX5_DmgAct 攻击方 I0Q9 分支
call HF22LS_Heal(src,dmg*0.30)   // dmg = GetEventDamage()
```

结果是普攻命中回一次、技能伤害也回一次、一次打多目标则每个目标各回一次，攻速越快回得越频繁。母图里同类吸血装备（真红白之圣灵剑 `I06O`）的做法是**带间隔**的：它的动作里 `DisableTrigger` → 结算 → `nY(1.)` → `EnableTrigger`，即 1 秒内不再重复结算。

v1.07 给沐浴鲜血加 **1.2 秒间隔**，语义与真红白一致——**节流，不累积**：间隔内造成的伤害不回血，1.2 秒后下一次造成伤害才再回一次。

实现沿用**母图自己的间隔写法**（母图把「一段时间内只做一次」统一交给 `PH_Bzv`）：

```jass
// note_log/work/hfx7_module.j（v1.07 版）
function HFX5_BloodReady takes unit u returns boolean
    if LoadInteger(PH_Xs,StringHash(I2S(GetHandleId(u))+"HFX5blood"),0)!=0 then
        return false                                    // 还在 1.2 秒间隔里 → 本次不回血
    endif
    call PH_Bzv(u,1.2,"HFX5blood")                       // 置位：1.2 秒后由母图定时器自动清位
    return true
endfunction
```

回血那一行随之包进判断：

```jass
if HFX5_BloodReady(src) then
    call HF22LS_Heal(src,dmg*0.30)
endif
```

`PH_Bzv`（`war3map.j:59037`）做的事就是「立刻把标记置 1 + 起一个一次性定时器，N 秒后把标记清 0」，母图自己的道具时限技能也用它，因此不需要额外的计时器或全局变量。

## 二、七皇の统治者：+10000 攻击/魔法为什么没落实

v1.05 给七皇の统治者（`I0H6`）新建了两个被动技能并把它们追加到物品技能栏：

| 技能 | 模板 | 效果 |
|---|---|---|
| `Y03F` | `A00P`（`AItn` 系） | `Iatt = 10000`（+10000 攻击） |
| `Y040` | `X018`（`AI2m` 系） | `Iman = 10000`（+10000 魔法值） |

排查（`note_log/work/230–235_probe_qihuang*.txt`）发现两件事：

1. **对象层没有问题**。`Y03F`/`Y040` 都在 `war3map.w3a` 的自定义表里，字段与模板逐字段一致，`I0H6.iabi` 里也确实写着它们；但**母图 551 件物品的技能栏（`iabi`）上限就是 6 条**（官方 2.43 `ItemData.slk` 的上限是 5 条；全图 6 条的只有 `I0H6` 与 `J0H6`）。追加后 `I0H6` 变成 **8 条**，第 7/8 条被引擎忽略 —— 与实测「没有效果」吻合。
2. **介绍栏从来没写过这两项**。母图的 `I0H6` 介绍栏（`ides`/`utub`）里只有筋力/敏捷/体力/生命值/魔法防御/防御和两个技能名，即便加成生效，玩家在物品说明里也看不到。

而母图自己对「大额攻击 / 全部魔法值」加成的做法是**走脚本的 EXEQ 装备系统**：`EXEQ_Reconcile`（`war3map.j:88137`，拾取/丢弃事件 + 每秒 `EXEQ_PeriodicReconcile` 都会跑）里有一串 `call EXEQ_Ability(EXEQL_u,'XXX',条件)`，其中 `X00R`/`X009` 就是 `AIat` 系攻击被动、`X018` 就是 `AI2m` 系魔法被动。

## 三、v1.07 的做法

- 物品技能栏**回到母图原有 6 条**（不再追加 `Y03F`/`Y040`；两个技能对象仍保留在 `war3map.w3a` 里，只是改由脚本授予）。
- 在 `EXEQ_Reconcile` 里插两行，按背包里是否持有 `I0H6` 授予/移除：

```jass
call EXEQ_Ability(EXEQL_u,'Y03F',EXEQ_Has(EXEQL_u,'I0H6'))
call EXEQ_Ability(EXEQL_u,'Y040',EXEQ_Has(EXEQL_u,'I0H6'))
```

`EXEQ_Ability` 自己用 `EXEQ_State` 记住状态（`UnitAddAbility` + `UnitMakeAbilityPermanent`，卸下时移除），而且 `EXEQ_Reconcile` 前后本来就保存/还原 maxHP/maxMP，属性变化不会引起掉血或蓝量异常。

- 介绍栏（`ides`/`utub`）补上两行：

| 项 | v1.06 | v1.07 |
|---|---|---|
| `I0H6.iabi` | `A0SA,A0PH,A0TE,Q15A,Q23R,Q23D,Y03F,Y040`（8 条，被忽略） | **`A0SA,A0PH,A0TE,Q15A,Q23R,Q23D`**（6 条）+ EXEQ 授予 |
| 介绍栏 | …生命值:10000 / 魔法防御:50… | …生命值:10000 / **攻击力:10000** / **魔法值:10000** / 魔法防御:50… |

## 五、验证与已知边界

- **数据层**：`validate.py` → 改动行 **216**｜错误 **0**｜警告 **0**；计划新增对象 物品 **10** ｜ 技能 **67**。
- **五层静态验证**（`note_log/work/verify_v107.py`）：**110 项通过 / 0 项失败** —— 逐字段回读 `I0H6.iabi` 回到 6 条且 `ides`/`utub` 含两行新数值、`Y03F`/`Y040` 对象仍在、脚本层 `call PH_Bzv(u,1.2,"HFX5blood")` 与 `if HFX5_BloodReady(src) then` 各 1 处、两条 `EXEQ_Ability` 授予各 1 处、`pjass` 零错误、标题三处为 `刀剑物语 happy丶FISH v1.07`、成员层差异（C→最终 3 个变更 + 9 个图标）、母图指纹未变。**仍未进游戏实测。**
- 已知边界：
  - 1.2 秒间隔是**节流**（间隔内的伤害不回血、不累积），与真红白之圣灵剑的间隔同语义；如果希望「攒到下一次一起回」需要另改实现。
  - 「物品技能栏上限」没有找到官方文档：Hive 的讨论只说明编辑器的 4 个槽位是**编辑器**限制（Shift+Enter 可填更多），运行时上限是以「官方最多 5 条、母图最多 6 条、且第 7/8 条实测无效」推断的 —— 因此本版不去赌这个上限，直接改走 EXEQ。
  - 第 24 条「抵抗」仍按 v1.05 拍板**暂不实现**。
